# Roadmap

План развития. Здесь живут только ещё не выполненные фазы; выполненные
удаляются — история остаётся в GitHub issues и в `openspec/specs/`. Фазы
выполняются по порядку сверху вниз; отдельной нумерации нет — идентификатор
фазы появляется вместе с issue.

Пока фаза не взята в работу, ни issue, ни change не создаются.

## Правило входа в работу

1. Берём верхнюю фазу из таблицы.
2. Создаём GitHub issue (одна фаза — один issue).
3. Создаём change с указанным именем; proposal ссылается на issue.
4. При архивации change закрываем issue, обновляем `docs/` и удаляем строку
   фазы из таблицы в том же коммите.
6. PR ставится на автослияние; агент дожидается прогона CI на PR и merge, но не
   ждёт прогон CI на `main` — его смотрит владелец. Красный `main` закрывается
   отдельным issue на фикс.

Issue не заводится заранее: он появляется вместе с проработкой идеи, а не
копится списком.

Suno как сервис недоступен: сеть ограничена Hugging Face, edge-tts и git
(`CONSTITUTION.md` п. 2.4). «Пение как у Suno» означает локальную модель,
генерирующую песню по тексту, — модель и подход выбираются фазой оценки.

## Отложено до востребования

- Docker/контейнер: только если понадобится перенос на другую машину.
- CUDA-сборка torch: документируется одной строкой, extra не делаем.
- Автоматический fallback между провайдерами TTS: переключение пока ручное, через UI.
- Voice cloning (кастомные голоса из голосовых собеседника).
- Публикация `docs/` как сайта (MkDocs/Pages) — когда станет тесно в Markdown.
