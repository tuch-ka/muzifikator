# Документация

Человекочитаемое описание проекта. Формальные спецификации — в
`openspec/specs/`; здесь — объяснение системы людям.

## Содержание

- [Архитектура](architecture.md) — компоненты, потоки, зависимости, ограничения.
- [Запуск и окружение](operations.md) — установка, переменные, типовые ошибки.
- `capabilities/` — по файлу на capability. Появляются при архивации change:
  черновик из change семантически вливается сюда. Формат: что это, как работает,
  потоки, отказы, как отлаживать. Без WHEN/THEN — это не спека.
- [Лицензии и внешние сервисы](licenses.md) — ограничения MusicGen и статус
  edge-tts.

## Правила

- Диаграммы — Mermaid в код-фенсах.
- Документ не противоречит спеке и ссылается на требования по имени.
- Документация обновляется при архивации change, а не «когда-нибудь потом».
