# Запуск и окружение

Запуск, окружение, установка ffmpeg, типовые ошибки.

## Что нужно

- Python 3.12 и `uv` (управление окружением и зависимостями).
- `ffmpeg` и `ffprobe` в `PATH` либо явно указанные пути.

## Установка инструментов

| Инструмент | macOS | Debian / Ubuntu | Fedora |
|---|---|---|---|
| ffmpeg (+ ffprobe) | `brew install ffmpeg` | `sudo apt install ffmpeg` | `sudo dnf install ffmpeg` (RPM Fusion) |
| uv | `brew install uv` | по явному разрешению владельца | по явному разрешению владельца |

`uv` ставится из Homebrew: другие способы установки тянут пакеты из источников,
не перечисленных в `CONSTITUTION.md` п. 2.4, и требуют отдельного разрешения
владельца.

Проверка:

```
uv --version
ffmpeg -version
ffprobe -version
```

Важно: некоторые сборки ffmpeg идут без `ffprobe`. Нужна сборка, где он есть
(BtbN, gyan.dev для Windows).

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HOST` | `127.0.0.1` | Адрес прослушивания |
| `PORT` | `8000` | Порт |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `DB_PATH` | `data/muzifikator.sqlite3` | Файл базы SQLite; каталог создаётся при старте |
| `TTS_CACHE_DIR` | `.cache/tts` | Каталог кэша озвучки |
| `TTS_CACHE_LIMIT_MIB` | `200` | Лимит кэша озвучки в МиБ; `0` — без лимита |
| `MUSICGEN_MODEL` | `facebook/musicgen-small` | Модель музыки |
| `MUSIC_MODELS_DIR` | `models` | Каталог весов модели |
| `MUSIC_PROMPT` | `folk metal` | Промпт стиля по умолчанию |
| `MUSIC_DEVICE` | `auto` | `auto`, `mps` или `cpu` |
| `MUSIC_MIN_DURATION_SECONDS` | `20` | Минимальная длительность итогового трека |
| `OUTPUT_DIR` | `~/muzifikator` | Каталог по умолчанию, если не сохранён в настройках |
| `OUTPUT_FORMATS` | `mp3,m4a` | Форматы результата через запятую |
| `FFMPEG_BIN` | не задана | Явный путь к `ffmpeg` (приоритет над `PATH`) |
| `FFPROBE_BIN` | не задана | Явный путь к `ffprobe` |

Значения можно положить в локальный `.env` в корне репозитория; файл в
`.gitignore` и не коммитится.

## Запуск

```
uv sync
uv run muzifikator
```

Эквивалент: `uv run python -m muzifikator`. `uv sync` ставит и dev-инструменты
(`pytest`, `ruff`); для проверок — `uv run pytest`, `uv run ruff check .`.

Успешный старт: в stderr строки preflight с путями и версиями бинарей, строки
хранилища о применённых миграциях, затем сообщение uvicorn о том, что сервис
слушает адрес. Проверка:

```
curl -s http://127.0.0.1:8000/api/health
```

## База данных

База — файл SQLite по умолчанию `data/muzifikator.sqlite3`; каталог создаётся
автоматически. Схема приводится к последней ревизии при каждом старте, ручные
команды не нужны.

Ручные команды для разработки:

```
uv run alembic upgrade head                    # применить миграции
uv run alembic downgrade -1                    # откатить одну ревизию
uv run alembic revision --autogenerate -m "…"  # заготовка новой миграции
uv run alembic current                          # текущая ревизия
```

`DB_PATH=/tmp/other.sqlite3 uv run alembic ...` работает: путь берётся из той же
конфигурации, что и приложением.

**База — ценный файл.** Перед обновлением приложения её стоит скопировать:
`cp data/muzifikator.sqlite3 data/muzifikator.sqlite3.bak`. Неудачная миграция
блокирует запуск, но не должна стоить истории. Копировать нужно на остановленном
сервисе (или вместе с файлами `-wal` и `-shm`).

Посмотреть содержимое:

```
sqlite3 data/muzifikator.sqlite3 '.tables'
sqlite3 data/muzifikator.sqlite3 'select id, status, stage, created_at from generations order by created_at desc limit 10;'
sqlite3 data/muzifikator.sqlite3 'select key, value from settings;'
```

## Кэш озвучки

Синтезированная речь лежит в `.cache/tts/` (меняется `TTS_CACHE_DIR`). Каждая
запись — пара файлов: `<ключ>.mp3` и `<ключ>.json` с параметрами и длительностью.
Ключ — хэш провайдера, голоса, темпа, тона, рыка и текста, поэтому одно и то же
не синтезируется дважды, в том числе после перезапуска.

Размер ограничен `TTS_CACHE_LIMIT_MIB` (по умолчанию 200 МиБ, `0` — без лимита).
При превышении удаляются записи, к которым дольше всего не обращались: время
обращения хранится в `mtime` файла `.mp3`, время создания — в `.json`.

```
du -sh .cache/tts                       # текущий размер
ls .cache/tts | head                    # записи кэша
cat .cache/tts/<ключ>.json              # параметры и длительность
rm -rf .cache/tts                       # полная очистка (безопасно)
```

Сетевые ошибки: закэшированная речь продолжает работать, новый текст даёт ошибку
синтеза с причиной. endpoint edge-tts неофициальный, его недоступность — не
повод менять провайдера без решения владельца (`CONSTITUTION.md` п. 5.2).

## Музыка

Музыка генерируется локально моделью MusicGen (`transformers`). Веса лежат в
`models/` (`MUSIC_MODELS_DIR`), вне репозитория. Первый запуск скачивает ~2,2 ГБ
с Hugging Face; дальше модель загружается из диска примерно за 3 секунды и
остаётся в памяти процесса.

Ориентиры на Apple M4 Pro (MPS): трек 10 с генерируется ~10 с, 40 с — ~35 с
(два сегмента с кроссфейдом). На CPU в разы медленнее — можно поставить
`MUSIC_DEVICE=cpu`, чтобы не занимать GPU, но ждать придётся дольше.

```
du -sh models                          # размер весов
du -sh models/*                        # по файлам
ls models/                             # что скачано
```

Кэша музыки нет: каждый запрос генерирует трек заново. Повторить прежний трек
можно, передав тот же `seed` и промпт.

## API задач

Постановка генерации возвращает идентификатор сразу; работа идёт в фоне.

```
curl -s -X POST localhost:8000/api/generations \
  -H 'content-type: application/json' \
  -d '{"text":"Привет, мир","voice":"ru-RU-DmitryNeural"}'

curl -s localhost:8000/api/generations/<id>        # состояние
curl -s 'localhost:8000/api/generations?limit=5'   # последние задачи
curl -s localhost:8000/api/voices                   # голоса провайдера
```

Параметры постановки: `text` (обязателен), `voice` (обязателен), `rate_percent`,
`pitch_hz`, `growl`, `music_tags`, `music_seed`, `formats`.

Коды: `202` задача принята, `400` неизвестный голос или формат, `409` уже идёт
другая генерация (её id в ответе), `422` пустой текст, `404` нет задачи, `502`
провайдер голосов недоступен.

Одновременно выполняется одна задача. После рестарта задача, прерванная в
`running`, читается как `failed` с причиной «прервано перезапуском» — её нужно
поставить заново.

## Пересоздание базы

Схема развивается без миграций данных. Если нужна чистая история (например, после
обновления кода), остановите сервис и удалите файл базы — при старте она создастся
заново существующими миграциями:

```
rm -f data/muzifikator.sqlite3 data/muzifikator.sqlite3-wal data/muzifikator.sqlite3-shm
```

Файлы в каталоге хранения при этом не удаляются, но приложению становятся
неизвестны: список строится по базе.

## Интерфейс

Откройте `http://127.0.0.1:8000/` — страница отдаётся самим сервисом, без
сборки и внешних CDN.

1. Введите текст; голос и теги музыки подставятся из сохранённых настроек.
2. Папка — необязательный подкаталог `OUTPUT_DIR`: пустое поле значит корень,
   `2026-11` создаст папку при генерации.
3. «Сгенерировать»: форма блокируется, прогресс идёт по стадиям «Озвучка»,
   «Музыка», «Микс». Если движок занят, интерфейс сообщит и продолжит ждать
   текущую задачу.
4. По завершении появятся файлы результата и обновится список файлов из базы.
5. «Перегенерировать» повторяет параметры с новым музыкальным seed — трек будет
   другим.
6. «Сохранить настройки» запоминает голос и теги для следующих сессий.

## Библиотека файлов

Список строится по базе: только файлы, созданные приложением, новые первыми.

```
curl -s 'localhost:8000/api/files?limit=5' | python3 -m json.tool
curl -s localhost:8000/api/storage
curl -s 'localhost:8000/api/storage/browse?path='
```

Проигрывание и открытие работают по записи, путь с клиента не принимается:

```
curl -s -o /dev/null -w '%{http_code}\n' \
  localhost:8000/api/generations/<id>/files/mp3/media
curl -s -X POST localhost:8000/api/generations/<id>/files/mp3/reveal
curl -s -X DELETE localhost:8000/api/generations/<id>
```

Удаление стирает файлы всех форматов и записи из базы: история не хранится.
`DELETE` отвечает `204`, при сбое удаления — `502` и записи остаются.

Обозреватель каталогов (`/api/storage/browse`) показывает только каталоги внутри
домашнего каталога пользователя; ручной ввод пути в интерфейсе проверяется
сервером (абсолютный, существует, каталог, доступен на запись).

## API настроек

```
curl -s localhost:8000/api/settings
curl -s -X PATCH localhost:8000/api/settings -H 'content-type: application/json' \
  -d '{"tts_voice":"ru-RU-DmitryNeural","music_tags":"folk metal","output_formats":["mp3","m4a"]}'
```

Ключи: `tts_voice`, `music_tags`, `rate_percent`, `pitch_hz`, `growl`,
`output_formats`. Неизвестный ключ или некорректное значение — `400`, ничего не
сохраняется. Настройки переживают перезапуск.

Постановка задачи без параметров берёт их из настроек: `voice` можно не
указывать, если он сохранён; явные значения в запросе главнее настроек.

## Результаты

Готовые файлы лежат в действующем каталоге хранения: по умолчанию
`~/muzifikator`, либо в сохранённом из интерфейса. Каталог создаётся сам.
Форматы — `OUTPUT_FORMATS` (`mp3,m4a` по умолчанию): MP3 VBR и AAC 192 кбит/с,
44,1 кГц, моно.

Имя файла: `YYYYMMDD-HHMMSS-<slug>.<ext>`. Время локальное; slug — латиница из
первых слов текста (`Привет, мир!` → `privet-mir`). Если имя занято, добавляется
`-2`, `-3`.

Микс: музыка приглушается под речь sidechain-компрессором, начинается с
нарастания 2 с, после речи звучит ещё 2 с и затухает. Громкость приводится к
−16 LUFS.

Длительность трека — большее из «речь + 2 с» и `MUSIC_MIN_DURATION_SECONDS`
(по умолчанию 20 с): после короткой фразы музыка звучит дольше и успевает
развернуться. Чтобы получить более короткий или длинный трек, поменяйте
переменную и перезапустите сервис.

```
curl -s 'localhost:8000/api/files?limit=5'        # что готово
ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 <файл>
ffmpeg -hide_banner -nostats -i <файл> -af ebur128 -f null -   # громкость
```

Временные файлы начинаются с `.tmp-`. Если процесс убили посреди микса, они
останутся без итоговых файлов — их можно удалить вручную в каталоге хранения.

## Типовые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| Процесс завершился с кодом 1, в выводе «не найден ffprobe» | Сборка ffmpeg без `ffprobe` | Поставить сборку с `ffprobe` |
| Процесс завершился, в выводе «путь из настроек не найден» | `FFMPEG_BIN`/`FFPROBE_BIN` указывает на несуществующий файл | Исправить путь или убрать переменную |
| `ffmpeg -version` работает в терминале, а preflight не находит | Разный `PATH` у терминала и у процесса (IDE, launchd) | Запускать из того же окружения или задать `FFMPEG_BIN` |
| `connection refused` на `/api/health` | Сервис не запущен | Смотреть stderr, причина отказа preflight там |
| `version: null` в health | Нестандартный формат вывода сборки | Не ошибка; проверить `ffmpeg -version` руками |
| Процесс завершился с кодом 1, в выводе «Не удалось открыть хранилище» | Нет прав на каталог, диск полон, миграция падает | Проверить права на `data/`, место на диске, текст ошибки миграции |
| `database is locked` | Второй экземпляр приложения на той же базе | Остановить лишний процесс; один файл — один сервис |
| Ошибка синтеза «Cannot connect to host» | Нет доступа к endpoint edge-tts | Проверить сеть; закэшированный текст продолжает работать |
| Кэш больше лимита | Лимит уменьшен, а вытеснение срабатывает после следующего синтеза | Дождаться синтеза или почистить `.cache/tts` вручную |
| Ошибка «не удалось загрузить модель» | Нет сети при первом запуске или не хватает места под `models/` (~2,2 ГБ) | Проверить сеть и место, повторить запуск |
| Ошибка «не хватило памяти» при генерации | MPS не тянет сегмент | Уменьшить длительность, закрыть лишнее или поставить `MUSIC_DEVICE=cpu` |
| Генерация идёт очень долго | Работа на CPU или тяжёлая модель | Проверить `MUSIC_DEVICE`, вернуться к `musicgen-small` |
| Процесс не стартует: «нет энкодеров aac» | Сборка ffmpeg без AAC | Поставить сборку с AAC (Homebrew и apt такие) |
| В `out/` только `.tmp-*` | Микс прервался до записи результата | Посмотреть stderr; удалить `.tmp-*` |
| Ошибка «музыка короче микса» | Музыку запросили без хвоста 2 с | Запрашивать музыку длиной «речь + 2 с» с запасом |

## Проверки перед PR

То же, что делает CI (подробности — `docs/ci.md`):

```
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest
openspec validate --specs
```

Модельные и сетевые тесты локально: `uv run pytest -m model` и
`uv run pytest -m network`; в CI они не идут.

## Каталоги

`models/`, `data/`, `logs/`, `.cache/`, `out/`, `.tools/` — вне репозитория
(`.gitignore`). `data/` создаётся при первом старте вместе с файлом базы; в
WAL-режиме рядом появляются `-wal` и `-shm`. Остальные каталоги появляются
вместе с фазами, которым они нужны.
