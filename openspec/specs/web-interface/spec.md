# web-interface Specification

## Purpose

Даёт UI то, что нужно до первой генерации и после неё: список готовых файлов в
выходном каталоге и сохранённые пользовательские настройки, которые применяются
к новым задачам.

## Requirements

### Requirement: Листинг файлов

Система SHALL отдавать содержимое каталога внутри выходного каталога:
относительный путь, абсолютный корень и записи с именем, относительным путём,
типом (файл или каталог), размером и временем изменения. Записи SHALL
сортироваться: сначала каталоги, затем по имени без учёта регистра.

#### Scenario: Корень по умолчанию

- **WHEN** запрошен листинг без пути
- **THEN** возвращается содержимое выходного каталога и его абсолютный путь

#### Scenario: Вложенный каталог

- **WHEN** запрошен листинг подкаталога
- **THEN** возвращается его содержимое, а пути записей — относительно корня

#### Scenario: Пустой каталог

- **WHEN** каталог существует и пуст
- **THEN** ответ содержит пустой список, а не ошибку

### Requirement: Защита путей

Система MUST NOT выходить за пределы выходного каталога: пути с `..`,
абсолютные пути и симлинки, ведущие наружу, SHALL отклоняться с кодом `400`.

#### Scenario: Выход через ..

- **WHEN** путь содержит `..` и выводит за корень
- **THEN** ответ `400`, содержимое не отдаётся

#### Scenario: Абсолютный путь

- **WHEN** путь начинается с `/`
- **THEN** ответ `400`

#### Scenario: Симлинк наружу

- **WHEN** симлинк внутри корня указывает за его пределы
- **THEN** ответ `400`

#### Scenario: Каталога нет

- **WHEN** путь внутри корня не существует
- **THEN** ответ `404`

#### Scenario: Путь указывает на файл

- **WHEN** запрошен листинг пути, который является файлом
- **THEN** ответ `400`

### Requirement: Чтение настроек

Система SHALL отдавать действующие значения настроек по белому списку: голос,
теги музыки, темп, тон, рык и форматы вывода. Если значение не сохранено,
возвращается действующее по умолчанию или `null`, если умолчания нет.

#### Scenario: Настройки не менялись

- **WHEN** запрошены настройки на чистой базе
- **THEN** возвращаются значения из конфигурации и умолчания, а голос — `null`

#### Scenario: Часть значений сохранена

- **WHEN** сохранён только голос
- **THEN** остальные значения приходят из конфигурации и умолчаний

### Requirement: Запись настроек

Система SHALL принимать частичное обновление настроек: указанные ключи
сохраняются, остальные не меняются. Неизвестный ключ или некорректное значение
SHALL отклоняться с кодом `400`; при отказе ничего не сохраняется.

#### Scenario: Частичное обновление

- **WHEN** переданы только `music_tags` и `growl`
- **THEN** меняются только они, остальные настройки остаются прежними

#### Scenario: Неизвестный ключ

- **WHEN** передан ключ вне белого списка
- **THEN** ответ `400` с именем ключа, настройки не меняются

#### Scenario: Некорректный формат вывода

- **WHEN** передан формат, которого система не умеет
- **THEN** ответ `400`, настройки не меняются

#### Scenario: Перезапуск

- **WHEN** настройки сохранены и процесс перезапущен
- **THEN** чтение возвращает сохранённые значения

### Requirement: Настройки как умолчания задачи

При постановке генерации отсутствующие параметры SHALL браться из сохранённых
настроек: теги музыки, темп, тон, рык и форматы. Голос MAY отсутствовать в
запросе, если он сохранён в настройках; иначе запрос отклоняется.

#### Scenario: Пустые параметры

- **WHEN** запрос содержит только текст, а настройки задают голос и теги
- **THEN** задача выполняется с этими настройками

#### Scenario: Нет ни голоса, ни настроек

- **WHEN** запрос без голоса, а в настройках голос не сохранён
- **THEN** ответ `422`, задача не создаётся

#### Scenario: Явный параметр главнее

- **WHEN** запрос содержит теги, отличные от настроек
- **THEN** используется значение из запроса, настройки не меняются

### Requirement: Статический интерфейс

Система SHALL отдавать одностраничный интерфейс по корневому адресу и его
ресурсы (HTML, CSS, JS) из собственного пакета. Интерфейс MUST NOT требовать
сборки, Node.js или внешних CDN и SHALL работать в браузере без установки
дополнительного ПО.

#### Scenario: Открытие интерфейса

- **WHEN** браузер запрашивает `/`
- **THEN** возвращается HTML-страница с формой генерации и подключёнными локальными ресурсами

#### Scenario: Ресурсы доступны

- **WHEN** страница загружает свои CSS и JS
- **THEN** файлы отдаются сервисом, а не внешними сайтами

### Requirement: Форма генерации

Интерфейс SHALL содержать текст, выбор голоса из списка провайдера, поле тегов
музыки и поле папки результата. Теги и голос SHALL предзаполняться сохранёнными
настройками, папка по умолчанию — пустая (корень). Пустой текст SHALL
блокировать отправку.

#### Scenario: Предзаполнение

- **WHEN** страница открыта и настройки сохранены
- **THEN** поля голоса и тегов содержат сохранённые значения

#### Scenario: Пустой текст

- **WHEN** текст пуст или состоит из пробелов
- **THEN** кнопка генерации недоступна, запрос не отправляется

### Requirement: Прогресс задачи в интерфейсе

После постановки интерфейс SHALL опрашивать состояние задачи и показывать
текущую стадию `tts`, `music` или `mix`, а по завершении — результат или текст
ошибки. Пока задача выполняется, повторная отправка формы SHALL блокироваться.

#### Scenario: Ход выполнения

- **WHEN** задача запущена
- **THEN** интерфейс показывает стадию, обновляя её по мере работы

#### Scenario: Ошибка задачи

- **WHEN** задача завершилась со статусом `failed`
- **THEN** интерфейс показывает текст ошибки и снова разрешает отправку

#### Scenario: Движок занят

- **WHEN** постановка вернула `409`
- **THEN** интерфейс сообщает, что уже идёт генерация, и не теряет введённые данные

### Requirement: Результат в интерфейсе

После успешной задачи интерфейс SHALL показывать список созданных файлов с
путями и обновлять листинг выбранной папки.

#### Scenario: Успешная генерация

- **WHEN** задача завершилась со статусом `done`
- **THEN** интерфейс показывает файлы результата и обновлённый список папки

#### Scenario: Пустая папка

- **WHEN** выбранная папка пуста
- **THEN** интерфейс показывает пустой список без ошибки

### Requirement: Перегенерация

Интерфейс SHALL предоставлять повторный запуск с теми же текстом, голосом,
тегами и папкой, но с новым музыкальным seed.

#### Scenario: Повтор с новым seed

- **WHEN** нажата кнопка перегенерации
- **THEN** создаётся новая задача с теми же параметрами, и результат отличается по seed

### Requirement: Настройки в интерфейсе

Интерфейс SHALL читать настройки при загрузке и сохранять изменённые значения
голоса, тегов и форматов через API настроек.

#### Scenario: Сохранение

- **WHEN** пользователь сохраняет настройки в интерфейсе
- **THEN** значения сохраняются и используются при следующем открытии страницы

#### Scenario: Отказ валидации

- **WHEN** сохранение настроек отклонено сервером
- **THEN** интерфейс показывает сообщение и не выдаёт сохранение за успешное

### Requirement: Папка результата в запросе

Постановка генерации SHALL принимать необязательный относительный подкаталог
внутри выходного каталога; несуществующий каталог создаётся, путь за пределы
корня или абсолютный путь SHALL отклоняться с кодом `400` до создания задачи.

#### Scenario: Подкаталог указан

- **WHEN** задача поставлена с папкой `2026-11`
- **THEN** файлы появляются в `OUTPUT_DIR/2026-11`, а ответ содержит пути в этой папке

#### Scenario: Неверная папка

- **WHEN** папка абсолютная или выводит за корень
- **THEN** ответ `400`, задача не создаётся
