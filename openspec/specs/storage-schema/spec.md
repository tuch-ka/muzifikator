# storage-schema Specification

## Purpose

Приводит схему базы к актуальной версии без ручных команд и не даёт приложению
работать на несовместимой или недоступной базе.

## Requirements

### Requirement: Расположение базы

Система SHALL брать путь к файлу базы из конфигурации (`DB_PATH`, по умолчанию
`data/muzifikator.sqlite3`) и SHALL создавать недостающий каталог при старте.
Файл базы MUST NOT находиться в системе контроля версий.

#### Scenario: Каталог данных отсутствует

- **WHEN** приложение стартует, а каталога с файлом базы нет
- **THEN** каталог создаётся, база создаётся пустой и сразу приводится к актуальной схеме

#### Scenario: Путь изменён настройкой

- **WHEN** `DB_PATH` указывает на другой файл
- **THEN** приложение использует именно этот файл

### Requirement: Автоматическое применение миграций

При старте система SHALL доводить схему базы до последней известной ревизии до
того, как начнёт обслуживать запросы.

#### Scenario: Новая база

- **WHEN** база пуста
- **THEN** создаются все таблицы и служебная таблица ревизий, и сервис стартует

#### Scenario: База уже актуальна

- **WHEN** схема соответствует последней ревизии
- **THEN** изменений не вносится, сервис стартует

#### Scenario: Повторный старт

- **WHEN** приложение запускается повторно на той же базе
- **THEN** данные сохраняются, повторное применение миграций ничего не меняет

### Requirement: Отказ при недоступной базе

Если базу нельзя открыть или миграции завершились ошибкой, система MUST NOT
начинать обслуживание запросов: она SHALL вывести одно сообщение с причиной и
завершиться с ненулевым кодом.

#### Scenario: База недоступна

- **WHEN** файл базы нельзя открыть из-за прав или каталог недоступен для записи
- **THEN** приложение печатает причину и завершается с ненулевым кодом, порт не открывается

#### Scenario: Миграция упала

- **WHEN** применение миграций завершается ошибкой
- **THEN** приложение не стартует, сообщение содержит текст ошибки миграции
