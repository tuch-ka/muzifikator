# Design

## Context

См. `proposal.md` — Why. Текущее состояние: репозиторий содержит только
`README.md`, `CONSTITUTION.md`, `ROADMAP.md`, `docs/` и пустой `openspec/specs/`;
кода нет. На машине разработчика отсутствуют `uv`, `ffmpeg` и `ffprobe`, поэтому
задачи проверки включают их установку.

Ограничения, влияющие на решение: `CONSTITUTION.md` п. 4.2 (модели, кэш, логи и
данные вне репозитория), п. 2.4 (разрешённая сеть — только HF, edge-tts и git),
`README.md` (при отсутствии ffmpeg приложение не запускается).

## Goals / Non-Goals

**Goals:**

- Один процесс, который можно запустить одной командой и который до первой
  генерации честно говорит, пригодно ли окружение.
- Конфигурация, к которой позже без переделки добавятся пути моделей, порт,
  каталоги вывода.
- Точка расширения: следующие фазы добавляют модули, а не переписывают каркас.

**Non-Goals:**

- Тестовая стратегия проекта и покрытие — фаза 10; здесь только минимальные
  проверки, доказывающие работоспособность preflight и health.
- Структура роутеров под будущие API, слои репозиториев, DI-контейнер.
- Упаковка в Docker, CI, линт-гейты в pre-commit.

## Decisions

### 1. Раскладка пакета

`src/muzifikator/` с модулями `config.py`, `logging_setup.py`, `preflight.py`,
`app.py` (FastAPI-приложение), `__main__.py` (точка входа). `pyproject.toml` в
корне, `[project.scripts] muzifikator = "muzifikator.__main__:main"`.

Альтернативы: плоский пакет в корне (захламляет корень, мешает `uv run`);
разделение на `api/`, `services/`, `core/` (преждевременно — один эндпоинт).

### 2. Конфигурация

`pydantic-settings` с классом `Settings`: `host` (127.0.0.1), `port` (8000),
`log_level` (INFO), `ffmpeg_bin`, `ffprobe_bin` (оба необязательные). Имена
переменных без префикса — `HOST`, `PORT`, `LOG_LEVEL`, `FFMPEG_BIN`,
`FFPROBE_BIN` — потому что `README.md` уже обещает пользователю именно
`FFMPEG_BIN`/`FFPROBE_BIN`. Поддерживается локальный `.env` (в `.gitignore` он
уже не числится — добавить).

Альтернативы: собственный парсинг `os.environ` (теряем валидацию и типы);
префикс `MUZIFIKATOR_` (ломает обещанные имена; можно ввести для новых,
специфичных полей позже).

### 3. Логирование

Стандартный `logging` с одним обработчиком в stderr, уровень из `LOG_LEVEL`,
формат `время уровень логгер сообщение`. Настройка — в `logging_setup.py`,
вызывается из точки входа до preflight, чтобы отказ тоже был в едином формате.
`uvicorn`-логгеры приводятся к тому же обработчику.

Альтернативы: `structlog`/JSON (лишняя зависимость и нечитаемый вывод в
терминале для локального инструмента), логирование в файл (запись в `logs/`
понадобится с фазой задач; сейчас stderr достаточно).

### 4. Контракт preflight

`preflight.py` отдаёт неизменяемый снимок:

- для каждого бинаря: `available`, `path | null`, `version | null`,
  `error | null`;
- `ok` = оба доступны.

Резолвинг: заданный путь из настроек → `shutil.which(name)`. Если заданный путь
не существует, он не откатывается молча на PATH: снимок несёт ошибку с этим
путём (иначе пользователь не поймёт, почему его настройка игнорируется).

Проверка: `subprocess.run([path, "-version"], timeout=5, capture_output=True)`.
Код 0 → пригоден; версия извлекается регуляркой `version\s+(\S+)` из stdout+stderr,
при неудаче — `null` (в health отображается как «неизвестно»). Ненулевой код →
`error` с кодом и последней строкой вывода; таймаут → `error` о таймауте
(`subprocess.run` сам убивает процесс при таймауте).

### 5. Момент отказа

Preflight вызывается в `main()` **до** `uvicorn.run`, поэтому порт не
открывается. При `ok = false` печатается одно сообщение со всеми проблемами,
подсказкой по установке (macOS, Debian/Ubuntu, Fedora) и упоминанием
`FFMPEG_BIN`/`FFPROBE_BIN`, затем `sys.exit(1)`.

Альтернативы: старт с деградацией и `503` на health (противоречит `README.md` и
маскирует проблему до первой генерации); проверка в `lifespan` (порт уже
занят, клиент видит таймаут вместо сообщения).

### 6. Health

`GET /api/health` → `200`:

```json
{
  "status": "ok",
  "app_version": "0.1.0",
  "binaries": {
    "ffmpeg": {"available": true, "path": "/opt/homebrew/bin/ffmpeg", "version": "7.1"},
    "ffprobe": {"available": true, "path": "/opt/homebrew/bin/ffprobe", "version": "7.1"}
  }
}
```

Снимок preflight кладётся в `app.state` при создании приложения; обработчик его
только сериализует. `app_version` — из `importlib.metadata`, при отсутствии
метаданных — `"unknown"`. Поля бинаря всегда присутствуют; `status` = `ok`
всегда, потому что при непригодном окружении процесс не стартует (отдельного
деградированного состояния в этой фазе нет).

### 7. Зависимости и проверка

Runtime: `fastapi`, `uvicorn`, `pydantic-settings`. Dev: `pytest`, `httpx`
(для `TestClient`), `ruff`.

Минимальные проверки (не стратегия тестирования, она в фазе 10): `pytest`
на preflight с подставными бинарями (успех, ненулевой код, таймаут, отсутствие)
и на `/api/health` (форма ответа). Плюс ручная проверка `curl` и запуск без
`ffmpeg` в `PATH` для проверки сообщения об отказе.

## Risks / Trade-offs

- Отсутствие `uv`, `ffmpeg`, `ffprobe` на текущей машине → установка входит в
  задачи; до неё проверка невозможна, это отмечено как блокер проверки, а не
  скрытая работа.
- Таймаут 5 с может быть мал на медленном диске в первый запуск бинаря →
  значение выносится в константу модуля, чтобы правка была в одном месте.
- Разные форматы вывода `-version` у сборок → версия необязательна, снимок не
  ломается при `null`.
- Отказ старта означает, что health недоступен в сломанном окружении →
  сознательный выбор: пользователь ближе к терминалу, чем к HTTP.
- Русский текст сообщения в Windows-консоли может отобразиться некорректно →
  пишем в `stderr`, при отказе допускаем `errors="replace"`; полноценная
  локализация не делается.
- `uvicorn.run` в `main()` затрудняет переиспользование приложения в тестах →
  поэтому `app.py` создаёт приложение фабрикой, а `main()` только обвязка.

## Migration Plan

Greenfield: миграции данных нет. Откат — revert коммита фазы; внешних
артефактов (БД, файлов, записей в трекере кроме закрытия issue) не появляется.

## Open Questions

Нет: значения по умолчанию (127.0.0.1, 8000, INFO, таймаут 5 с) выбраны
осознанно и меняются конфигурацией, не кодом.
