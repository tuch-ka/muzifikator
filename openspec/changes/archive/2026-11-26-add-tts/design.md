# Design

## Context

См. `proposal.md` — Why. Есть `Settings` (`DB_PATH`, `FFMPEG_BIN`, `FFPROBE_BIN`),
снимок preflight с разрешёнными путями бинарей и синхронное хранилище на
SQLAlchemy. WSGI-слой — FastAPI; фаза 6 будет выполнять генерацию в пуле потоков.
`edge-tts` — асинхронная библиотека, обращающаяся к неофициальному endpoint
Microsoft (`CONSTITUTION.md` п. 5.2). Каталог `.cache/` уже в `.gitignore`.

## Goals / Non-Goals

**Goals:**

- Провайдер за протоколом, чтобы второй (Piper, фаза 9) не трогал сервис, кэш и
  обработку.
- Один и тот же текст не синтезируется дважды, включая после перезапуска.
- Длительность, на которую можно опираться при миксе.

**Non-Goals:**

- Стриминг, частичная отдача, прогресс синтеза (фаза 6 — про прогресс задачи,
  не про аудио).
- Очистка кэша по возрасту и настройка лимита из UI (только конфигурация).
- Управление голосами: выбор, избранное, фильтры — это UI и настройки (фазы 7–8).
- Нормализация громкости: этим занимается микс (фаза 5).

## Decisions

### 1. Раскладка и зависимости

```
src/muzifikator/speech/__init__.py
src/muzifikator/speech/base.py     # протокол, dataclass'ы, ошибки
src/muzifikator/speech/edge.py     # EdgeTTSProvider
src/muzifikator/speech/cache.py    # ключи, sidecar-метаданные, атомарная запись
src/muzifikator/speech/audio.py    # concat, growl, ffprobe
src/muzifikator/speech/service.py  # SpeechService: оркестрация
```

Зависимость `edge-tts`. `ffmpeg`/`ffprobe` — не новые зависимости, а уже
обязательные бинари; их пути приходят из снимка preflight.

Альтернатива: один модуль `tts.py` — к концу фазы в нём смешались бы сеть,
ffmpeg и кэш.

### 2. Синхронный интерфейс поверх асинхронного edge-tts

Протокол `SpeechProvider` синхронный:
`name`, `max_text_length`, `list_voices() -> list[Voice]`,
`synthesize(request, target: Path) -> None`.

Мост к async — в одном месте, `_run_sync(coro)`: если в текущем потоке уже
крутится event loop, поднимается понятная ошибка, иначе `asyncio.run`.

Почему так: хранилище и ffmpeg синхронные, фаза 6 запускает работу в пуле
потоков (обычные `def`-обработчики FastAPI). Асинхронный протокол протянул бы
`async` через репозиторий и микс, где он не нужен.

Альтернативы: полностью async-стек (`aiosqlite`, async SQLAlchemy) — переписывать
фазу 2; `nest_asyncio` — лишняя зависимость и скрытые вложенные циклы.

### 3. Разделение ответственности провайдера и сервиса

Провайдер умеет только «текст → файл в указанном месте» и «список голосов».
Сервис владеет кэшем, разбиением длинного текста, склейкой, рыком и длительностью.
Поэтому второй провайдер (фаза 9) не знает про кэш и ffmpeg-фильтры, а кэш
одинаково работает для любого провайдера.

### 4. Ключ кэша

`sha256` от канонического JSON `{provider, voice, rate_percent, pitch_hz, growl,
text}` → первые 32 hex-символа. Файл `<key>.mp3`, рядом `<key>.json`:
провайдер, голос, параметры, длительность, длина текста, `created_at`,
`sha256 текста`.

Кэш попап считается только при наличии обоих файлов и совпадении параметров в
sidecar; иначе запись пересоздаётся. Длительность берётся из sidecar — повторный
запрос не запускает `ffprobe` (спека требует «прежнюю длительность»).

Альтернатива: ключовать по хешу текста и хранить варианты в одной папке —
сложнее искать и чистить; плоский `<key>.mp3` проще.

### 5. Лимит кэша и вытеснение (LRU)

Лимит — `Settings.tts_cache_limit_mib` (переменная `TTS_CACHE_LIMIT_MIB`, по
умолчанию 200 МиБ, `0` — без лимита, отрицательное отвергается валидацией
настроек). Размер считается обходом каталога (`.mp3` + `.json`) после записи
новой пары; счётчик не хранится, поэтому не расходится с диском.

Вытеснение — чистый LRU по времени последнего обращения. Обращение к записи
обновляет его через `os.utime` на `.mp3` (время создания живёт в sidecar), затем
удаление идёт от самого давнего, пока размер не опустится до лимита. Порядок
удаления стабилен: сначала `<key>.mp3`, затем `<key>.json`.

Только что записанная пара имеет самое свежее обращение и потому не попадает под
вытеснение. Ошибка удаления (права, занятый файл) не ломает синтез: предупреждение
в лог, кэш остаётся больше лимита до следующей попытки.

Альтернативы: LRU с окном защиты свежих записей — отклонено владельцем как
лишняя сущность; удаление по возрасту — отклонено, часто используемые записи
уходили бы наравне с забытыми.

### 6. Атомарная запись

Синтез и обработка идут во временный подкаталог внутри каталога кэша, затем
`os.replace` переносит `<key>.mp3` и `<key>.json`. Оборванный синтез не оставляет
файла, который потом считался бы кэшем (требование «частично записанный файл
MUST NOT оставаться»).

### 7. Разбиение длинного текста

Провайдер объявляет `max_text_length` (у edge-tts — с запасом, 3000 символов).
Сервис режет текст по границам предложений (`(?<=[.!?…])\s+`), набирая порции не
длиннее лимита; предложение длиннее лимита режется жёстко по словам. Порции
синтезируются по порядку и склеиваются `ffmpeg -f concat` с перекодированием в
MP3.

Проверка «без потери текста»: склейка порций, нормализованная по пробелам,
совпадает с нормализованным исходником.

Альтернатива: отдавать длинный текст провайдеру целиком — edge-tts вернёт ошибку
или обрежет, и пользователь потеряет часть сообщения.

### 8. Обработка «рык»

При `growl=True` после склейки применяется фильтр:

```
asetrate=48000*0.82,aresample=48000,atempo=1.21951,
acrusher=bits=8:mode=log:mix=0.35,
equalizer=f=110:width_type=h:width=100:g=5,
alimiter=limit=0.95
```

`asetrate` понижает тон и замедляет, `atempo` возвращает исходную скорость —
длительность сохраняется, тон остаётся низким. `acrusher` даёт сатурацию,
`equalizer` подчёркивает низ, `alimiter` не даёт перегруза. Константы — в
`audio.py`; их подбор не меняет поведение из спеки, только звучание.

Альтернатива: рычащие вставки между фразами — отклонено владельцем; это
потребовало бы отдельного синтеза, выравнивания по паузам и своей ветки кэша.

### 9. Список голосов

Провайдер держит список в поле экземпляра: первый вызов идёт в сеть, дальше
возвращается он же. Экземпляр живёт в состоянии приложения (создаётся один раз в
`main()`), поэтому «не более одного раза за процесс» выполняется естественно.

Ошибка получения списка поднимается как `VoiceListError`; пустой список не
возвращается (спека прямо это запрещает).

### 10. Ошибки

`SpeechError` — база; `SynthesisError`, `VoiceListError`, `UnknownVoiceError`,
`AudioProcessingError`. Сообщения на русском, с причиной (сеть, код, путь к
файлу). Провайдер ловит исключения edge-tts/httpx и оборачивает их, чтобы
наверх не протекали типы сторонней библиотеки.

### 11. Проверка

Юнит-тесты на фейковом провайдере (пишет тишину через `ffmpeg` в целевой файл,
считает вызовы): кэш-промах и попадание, смена параметра, перезапуск сервиса на
том же каталоге, разбиение длинного текста (число вызовов провайдера и один
выходной файл), пустой текст, рык (длительность ±0,2 с), ошибка `ffprobe` на
битом файле. Лимит: при превышении уходят самые давние, только что записанная
остаётся, `0` отключает вытеснение, ошибка удаления не роняет синтез. Сетевой тест edge-tts — маркер `network`, по умолчанию не
запускается; ручная проверка — в задачах.

`ffmpeg` в тестах обязателен, он и так требуется для запуска приложения.

## Risks / Trade-offs

- Неофициальный endpoint edge-tts может ограничить или изменить протокол →
  ошибка синтеза вместо тихого сбоя, кэш сохраняет уже полученное, второй
  провайдер в фазе 9.
- `asyncio.run` внутри синхронного API нельзя вызывать из работающего цикла →
  явная ошибка в `_run_sync`; вызывающий код — пул потоков.
- Перекодирование MP3 при склейке и рыке теряет немного качества → приемлемо для
  локального черновика; при необходимости формат меняется в `audio.py`.
- Лимит проверяется после записи, а не в фоне: при кэше сильно больше лимита
  одна генерация может удалить много файлов сразу → лишний разбор каталога,
  зато предсказуемый размер; кэш личный, объёмы небольшие.
- Чистый LRU без окна защиты может удалить файл, который читает другой процесс →
  сценарий исключён архитектурой: одна генерация одновременно (фаза 6), а свежая
  запись всегда самая молодая и первой не вытесняется.
- Время обращения живёт в `mtime` файла: внешние инструменты, переписывающие
  файл, сбивают порядок → кэш пересоздаст запись, потеря допустима.
- Рык — вкусовой эффект, пресет подобран на слух → константы в одном месте,
  подстройка без изменения спеки.
- Кэш по полному тексту делает копии для каждого варианта параметров → для
  личного инструмента приемлемо.

## Migration Plan

Схема БД не меняется, миграций нет. Появление: `uv sync` (добавляется
`edge-tts`), запуск как раньше. Кэш создаётся при первом синтезе. Откат —
удалить `.cache/tts/` и revert коммита.

## Open Questions

Нет: значение `max_text_length` для edge-tts и параметры рыка подбираются
константами в коде и не меняют контрактов.
