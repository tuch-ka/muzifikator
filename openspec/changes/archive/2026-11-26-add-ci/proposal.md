# Proposal

## Why

Сейчас всё проверяется руками: линт, тесты и валидация спек запускаются только
локально, а merge ветки в `main` ничем не подтверждён. Ошибка, найденная после
merge, всплывает уже в следующей фазе — это дороже, чем красный PR.

## What Changes

- Появляется workflow GitHub Actions: `ruff check`, `ruff format --check`,
  `mypy` в строгом режиме для `src/`, `pytest` (маркеры `network` и `model`
  исключены), `openspec validate` для активных change и всех спек, `uv build` с
  проверкой установки wheel.
- Появляется проверка типов: `mypy` со `strict = true` для `src/muzifikator`,
  тесты не проверяются; типы `torch`/`transformers` не анализируются
  (`ignore_missing_imports`), иначе CI тянул бы ~1 ГБ ради стабов.
- CI не устанавливает `torch` и `transformers`: тестам они не нужны. Для этого
  слой музыки импортирует их лениво, а `numpy` становится явной зависимостью
  (сейчас он приходит транзитивно). Локальная установка и запуск не меняются.
- Workflow запускается на `pull_request` в `main`, на `push` в `main` и вручную
  (`workflow_dispatch`) — ручной запуск нужен, чтобы проверить сам CI до PR.
- `torch` для Linux ставится из CPU-индекса PyTorch: CI тянет ~200 МБ вместо
  CUDA-колеса на несколько гигабайт. Установка на macOS не меняется.
- Появляется `docs/ci.md`: что проверяется, как повторить локально, как смотреть
  упавший прогон, какие настройки репозитория нужны.

Явно вне скоупа: CD и релизы, публикация артефактов, матрица версий Python и ОС,
macOS-раннеры, покрытие кодом, Dependabot, кэш моделей между прогонами.

## Capabilities

Нет. `openspec/changes/add-ci/.openspec.yaml` содержит `skip_specs: true`:
поведение продукта не меняется, меняется способ его проверки. Спека описывает
поведение системы, а не пайплайн проверок, — придумывать требование ради
валидатора не нужно.

## Impact

- Файлы: `.github/workflows/ci.yml`, `docs/ci.md`.
- Зависимости: `pyproject.toml` получает `numpy` явно, dev-зависимость `mypy`,
  настройки `[tool.mypy]`, CPU-индекс PyTorch для Linux и источник `torch` с
  маркером платформы; `uv.lock` пересобирается.
- Код: `music/backend.py` — ленивые импорты `torch`/`transformers`, типы под
  `TYPE_CHECKING`; импорт пакета `muzifikator.music` перестаёт требовать torch.
- CI: ubuntu-latest, `ffmpeg` из apt, OpenSpec CLI `@fission-ai/openspec@2.1.1`
  из npm; секретов не требуется.
- Настройки репозитория (вручную, владельцем): сделать проверку `CI`
  обязательной для merge в `main`.
- Трекер: GitHub issue `tuch-ka/muzifikator#5`.
- Внешних записей нет; сеть — только за зависимостями и клонированием в CI.
