# Design

## Context

См. `proposal.md` — Why. Есть: `paths.resolve_within`, листинг файловой системы в
`api/files.py`, `generation_files` с путями (часть относительна), `SettingsStore`
с белым списком, `AssemblyService` с `subdir`, пайплайн с `folder`. UI: форма с
полем папки и список имён. Владелец выбрал один настраиваемый корень, обозреватель
под `$HOME`, список из БД, доступ по id, дефолт `~/muzifikator`, удаление целой
генерации и пересоздание локальной базы вместо миграции данных.

## Goals / Non-Goals

**Goals:**

- Выбор каталога переживает перезапуск и реально влияет на запись.
- Список, проигрывание, открытие и удаление работают только по данным базы.
- Клиент не присылает пути к файлам.

**Non-Goals:**

- Загрузка и переименование файлов, перемещение существующих при смене каталога.
- Восстановление старых записей: история очищается.
- Просмотр файлов вне `$HOME` в обозревателе.

## Decisions

### 1. Пути

`paths.py` дополняется:

```python
project_root() -> Path          # переносится из storage.db
expand(raw: str | Path) -> Path # ~ -> home, resolve(strict=False)
is_inside(child, parent) -> bool
home_root() -> Path
storage_dir(raw: str) -> Path   # валидация каталога хранения
```

`storage_dir`: раскрыть `~`, требовать абсолютный путь, существование, каталог,
`os.access(W_OK)`. Проверка «вне репозитория» не делается — решение владельца.

По умолчанию каталог — `~/muzifikator`; `Settings` хранит `Path("~/muzifikator")`,
раскрытие при использовании.

### 2. Настройка `output_dir`

`SettingsStore` получает `default_output_dir` (из `Settings`) и ключ `output_dir`.
Валидация — `paths.storage_dir`, хранение — нормализованная строка абсолютного
пути, метод `effective_output_dir()` — действующий каталог. `OUTPUT_DIR` из
окружения остаётся первичным значением.

### 3. Абсолютные пути без миграции

Новые записи `generation_files.path` — абсолютные: сборка получает абсолютный
каталог. Совместимости с относительными путями нет.

Миграций данных не добавляется: приложение нигде не развёрнуто, локальная база
пересоздаётся вручную (`rm data/muzifikator.sqlite3*`), схема создаётся с нуля
существующими миграциями. Это проще и честнее, чем удаляющая данные миграция.

### 4. Каталог задачи из настроек

`JobDeps` получает `resolve_output_dir: Callable[[], Path]`; пайплайн в начале
задачи берёт действующий каталог, создаёт его при необходимости и передаёт в
`AssemblyRequest.output_dir`; временный каталог музыки — там же.

`AssemblyRequest` теряет `subdir`, получает `output_dir: Path | None`; сервис
использует переданный каталог или свой (для тестов). Смена настройки действует на
следующие задачи; текущая пишет в захваченный путь. Недоступный диск → задача
`failed` с текстом.

### 5. API библиотеки

`api/files.py` удаляется, вместо него `api/library.py`:

| Метод | Путь | Смысл |
|---|---|---|
| GET | `/api/files?limit=50&offset=0` | список из БД, новые первыми, `has_more` |
| GET | `/api/generations/{gid}/files/{format}/media` | байты файла, `Range` |
| POST | `/api/generations/{gid}/files/{format}/reveal` | открыть в менеджере ОС |
| DELETE | `/api/generations/{gid}` | удалить генерацию целиком |
| GET | `/api/storage` | действующий каталог |
| GET | `/api/storage/browse?path=` | подкаталоги внутри `$HOME` |

Список: `generation_id`, `format`, `name`, `path`, `exists`, `size`,
`created_at`, `duration_seconds`. Отсутствие файла запись не скрывает.

Медиа: нет строки → `404`; файла нет → `404`; иначе `FileResponse` с типом по
расширению (Starlette сам отдаёт `206`).

Открытие: проверка существования, затем `reveal_command(path, platform)`; сбой →
`502`.

Удаление: берутся все файлы генерации; каждый удаляется, `FileNotFoundError`
игнорируется; любая другая ошибка → `502` и записи остаются; после успешного
удаления файлов удаляется запись `generations` (связанные строки — каскадом или
явно), ответ `204`. Отсутствующая генерация → `404`.

Обозреватель: по умолчанию `$HOME`; только внутри `$HOME`, только каталоги в
списке; `parent` — `null` на `$HOME`; ручной ввод валидируется `storage_dir` и
`$HOME` не ограничен (escape hatch для внешних дисков).

### 6. Интерфейс

- Форма без поля папки.
- Блок «Каталог хранения»: текущий путь, «Изменить» → панель с текущим местом,
  «Выше», списком каталогов, полем ручного пути и «Выбрать»; сохранение через
  `PATCH /api/settings`.
- Список файлов из `/api/files`: имя, дата, длительность, формат, кнопки
  «Проиграть» (аудио), «Показать», «Удалить» (на генерацию, с `confirm`),
  «Показать ещё» при `has_more`. У отсутствующих файлов проигрывание и открытие
  недоступны, удаление доступно (чистит запись).
- Плеер — скрытый `<audio>`, источник — медиа-эндпоинт по id.
- Все данные — `textContent`.

### 7. Проверка

- `paths`: валидация каталога (относительный, отсутствует, файл, без прав,
  корректный), границы `$HOME`.
- Чистый старт: удалённая локальная база создаётся заново, список пуст, первая
  генерация сохраняет абсолютный путь.
- Настройки: сохранение/чтение `output_dir`, отказы, дефолт `~/muzifikator`,
  сохранность между приложениями.
- Библиотека: список только из БД, порядок и `has_more`, `exists`; медиа
  `200`/`206`/`404`; открытие (команды по платформам, `502`); удаление (файлы и
  записи исчезают, нет файла — успех, нет прав — `502` и записи на месте, нет
  генерации — `404`); обозреватель.
- Пайплайн: каталог из настроек, абсолютный путь в БД.
- UI: блок каталога и плеер есть, поля папки нет; вызовы новых эндпоинтов.
- Ручная проверка браузером: смена каталога, генерация, проигрывание, открытие и
  удаление.

## Risks / Trade-offs

- Базу нужно пересоздать вручную (шаг в документации): забытый шаг оставит
  старые относительные пути, и такие записи будут помечены отсутствующими.
- Файлы прежних версий остаются на диске «сиротами» → пользователь удаляет их
  сам; приложение их не показывает.
- Запись разрешена в любой каталог, обозреватель ограничен `$HOME` → внешние
  диски достижимы ручным вводом; это компромисс.
- Медиа, открытие и удаление доверяют путям из БД → локальная правка SQLite может
  указать на чужой файл; модель угроз — локальный владелец машины.
- Удаление необратимо и стирает файлы → UI требует подтверждения; ошибки удаления
  оставляют записи, чтобы можно было повторить.
- Старые файлы не переносятся при смене каталога → список смешанный.
- На Linux «показать» открывает папку; m4a в Firefox может не играть.

## Migration Plan

1. Удалить локальную базу: `rm -f data/muzifikator.sqlite3 data/muzifikator.sqlite3-wal data/muzifikator.sqlite3-shm`.
2. Запустить приложение: база создаётся заново существующими миграциями.
3. Дефолт `OUTPUT_DIR` меняется на `~/muzifikator`; каталог создаётся при первой
   задаче. Откат кода — revert коммита.
