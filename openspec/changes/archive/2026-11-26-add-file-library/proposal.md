# Proposal

## Why

Сейчас листинг показывает файловую систему под фиксированным `OUTPUT_DIR`, а
папку нельзя выбрать. Пользователь хочет сам решать, куда складывать треки,
видеть только созданные приложением файлы, проигрывать и открывать их, а также
удалять ненужное. Пути должны храниться в базе, чтобы список не зависел от
содержимого диска.

## What Changes

- Появляется настройка каталога хранения (`output_dir`) через API и интерфейс:
  абсолютный путь, существует, каталог, доступен на запись. `OUTPUT_DIR` из
  окружения — значение по умолчанию (`~/muzifikator`).
- Появляется обозреватель каталогов в UI: подкаталоги под `$HOME`, подъём выше,
  ручной ввод абсолютного пути; проверка — серверная.
- Пути файлов в базе становятся абсолютными.
- Список файлов отдаётся из базы: только известные приложению файлы, новые
  первыми, с признаком «на диске нет»; листинг файловой системы убирается.
- Проигрывание и открытие в менеджере работают по идентификатору записи
  (`generation_id` + `format`); путь от клиента не принимается.
- Появляется удаление генерации целиком: файлы на диске стираются, записи из
  базы удаляются — история не хранится.
- Подпапки результата (`folder`) убираются: один выбираемый корень.
- Совместимость со старыми путями не делается: приложение нигде не развёрнуто,
  локальная база просто пересоздаётся (чистый инстанс SQLite), данные не
  переносятся. Новых миграций не требуется.

Явно вне скоупа: загрузка и переименование файлов, удалённый доступ,
автоматическое создание произвольных каталогов, скачивание не-аудио.

## Capabilities

### Modified Capabilities

- `output-files`: «Выходной каталог» становится настраиваемым; добавляется
  требование об абсолютных путях; «Подкаталог результата» удаляется.
- `persisted-settings`: добавляется ключ `output_dir` с правилами валидации.
- `web-interface`: листинг заменяется списком из базы; добавляются обозреватель,
  выбор каталога, проигрывание, открытие и удаление по id; «Защита путей» и
  «Папка результата в запросе» удаляются.

## Impact

- Код: `paths.py` (абсолютные пути, каталог хранения), `api/settings_store.py`,
  новый `api/library.py`, удаление `api/files.py`; `assembly` — каталог из
  запроса; `jobs` — каталог из настроек в момент запуска; `web/` — обозреватель,
  список, плеер и удаление.
- Данные: схема не меняется; `generation_files.path` хранит абсолютные пути.
  Локальная база пересоздаётся вручную, миграций нет.
- Документация: три capability-дока, `docs/operations.md`,
  `docs/architecture.md`, `README.md`.
- Трекер: GitHub issue `tuch-ka/muzifikator#17`.
- Сеть не затрагивается; открытие окон — локальная команда ОС.
