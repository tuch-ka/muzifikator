# Spec Delta

## MODIFIED Requirements

### Requirement: Форма генерации

Интерфейс SHALL содержать текст, выбор голоса из списка провайдера и поле тегов
музыки. Теги и голос SHALL предзаполняться сохранёнными настройками. Пустой
текст SHALL блокировать отправку. Поля папки результата нет: каталог хранения
выбирается отдельно.

#### Scenario: Предзаполнение

- **WHEN** страница открыта и настройки сохранены
- **THEN** поля голоса и тегов содержат сохранённые значения

#### Scenario: Пустой текст

- **WHEN** текст пуст или состоит из пробелов
- **THEN** кнопка генерации недоступна, запрос не отправляется

### Requirement: Результат в интерфейсе

После успешной задачи интерфейс SHALL показывать файлы результата с путями и
обновлять список файлов из базы.

#### Scenario: Успешная генерация

- **WHEN** задача завершилась со статусом `done`
- **THEN** интерфейс показывает файлы результата и обновлённый список

#### Scenario: Пустая папка

- **WHEN** в базе ещё нет ни одного файла
- **THEN** интерфейс показывает пустой список без ошибки

### Requirement: Настройки в интерфейсе

Интерфейс SHALL читать настройки при загрузке и сохранять изменённые значения
голоса, тегов, форматов и каталога хранения через API настроек.

#### Scenario: Сохранение

- **WHEN** пользователь сохраняет настройки в интерфейсе
- **THEN** значения сохраняются и используются при следующем открытии страницы

#### Scenario: Отказ валидации

- **WHEN** сохранение настроек отклонено сервером
- **THEN** интерфейс показывает сообщение и не выдаёт сохранение за успешное

## ADDED Requirements

### Requirement: Список файлов из базы

Система SHALL отдавать список файлов из базы, а не из файловой системы: только
записи, созданные приложением, новые первыми, с ограничением количества и
признаком наличия на диске. Для каждой записи SHALL быть известны генерация,
формат, путь, имя, время создания и длительность.

#### Scenario: Файлы есть

- **WHEN** запрошен список
- **THEN** возвращаются записи новых генераций первыми, каждая с генерацией, форматом и путём

#### Scenario: Файл удалён с диска

- **WHEN** записи из базы соответствует отсутствующий файл
- **THEN** запись остаётся в списке с признаком «на диске нет»

#### Scenario: Чужие файлы

- **WHEN** в каталоге хранения лежит файл, созданный не приложением
- **THEN** в списке его нет

### Requirement: Обозреватель каталогов

Интерфейс SHALL позволять выбрать каталог хранения: показывать подкаталоги
текущего каталога, позволять подняться выше и ввести абсолютный путь вручную.
Обозреватель SHALL показывать только каталоги внутри домашнего каталога
пользователя; ручной ввод принимается только после серверной валидации.

#### Scenario: Переход по подкаталогам

- **WHEN** пользователь открывает обозреватель
- **THEN** видны подкаталоги текущего места и возможность подняться выше до домашнего каталога

#### Scenario: Выход за HOME

- **WHEN** запрошен каталог вне домашнего каталога
- **THEN** ответ `400`, содержимое не отдаётся

#### Scenario: Ручной ввод

- **WHEN** пользователь вводит абсолютный путь
- **THEN** путь проверяется так же, как настройка, и при успехе становится действующим каталогом

### Requirement: Проигрывание файлов

Система SHALL отдавать файл по идентификатору записи о генерации и формату, с
типом содержимого по расширению и поддержкой перемотки через `Range`. Если
записи нет — `404`; если файла нет на диске — `404` с понятным сообщением.

#### Scenario: Аудио отдаётся

- **WHEN** запрошен существующий файл записи
- **THEN** ответ `200` с типом содержимого и заголовком `accept-ranges`

#### Scenario: Перемотка

- **WHEN** запрос содержит `Range: bytes=0-1023`
- **THEN** ответ `206` с `Content-Range`

#### Scenario: Файла нет на диске

- **WHEN** файл записи удалён вручную
- **THEN** ответ `404`, интерфейс сообщает, что файл отсутствует

### Requirement: Открытие в файловом менеджере

Система SHALL по идентификатору записи открывать файл средствами ОС: на macOS
выделять в Finder, на Windows — в Explorer, на Linux открывать каталог файла.
Сбой команды SHALL возвращать `502` с причиной.

#### Scenario: Файл выделен

- **WHEN** запрошено открытие существующего файла
- **THEN** выполняется команда ОС и ответ успешен

#### Scenario: Команда ОС не сработала

- **WHEN** команда завершилась с ошибкой
- **THEN** ответ `502` с текстом причины

### Requirement: Удаление генерации

Система SHALL удалять генерацию целиком по её идентификатору: файлы всех
форматов стираются с диска, записи о генерации и её файлах удаляются из базы.
Отсутствие файла на диске не является ошибкой; при сбое удаления записи из базы
не удаляются. Действие необратимо.

#### Scenario: Удаление с файлами

- **WHEN** запрошено удаление генерации с существующими файлами
- **THEN** файлы удалены с диска, записи удалены из базы, список их больше не содержит

#### Scenario: Файл уже удалён вручную

- **WHEN** файла нет на диске
- **THEN** удаление проходит успешно, записи из базы удаляются

#### Scenario: Нет прав на файл

- **WHEN** файл не удаётся удалить
- **THEN** ответ `502`, записи в базе остаются, интерфейс показывает причину

#### Scenario: Неизвестная генерация

- **WHEN** запрошено удаление несуществующей генерации
- **THEN** ответ `404`

### Requirement: Плеер, кнопки и удаление в интерфейсе

Интерфейс SHALL позволять проигрывать аудиофайлы встроенным плеером, открывать
запись в менеджере и удалять генерацию. Удаление SHALL требовать подтверждения.
У записей без файла на диске кнопки проигрывания и открытия недоступны; ошибки
SHALL показываться текстом.

#### Scenario: Проигрывание

- **WHEN** пользователь нажимает «проиграть» у аудиофайла
- **THEN** плеер получает файл по id записи и воспроизводит его

#### Scenario: Удаление

- **WHEN** пользователь подтверждает удаление генерации
- **THEN** кнопка недоступна до завершения, а список обновляется после успеха

#### Scenario: Файл отсутствует

- **WHEN** у записи нет файла на диске
- **THEN** кнопки проигрывания и открытия недоступны с пояснением

## REMOVED Requirements

### Requirement: Листинг файлов

**Reason**: список отдаётся из базы (см. «Список файлов из базы»); листинг
файловой системы показывал посторонние файлы.

**Migration**: интерфейс переключается на список из базы; API листинга каталога
удаляется.

### Requirement: Защита путей

**Reason**: клиент больше не присылает пути для файлов — доступ идёт по id записи;
проверка путей остаётся только в обозревателе каталогов (граница `$HOME`) и в
валидации настройки `output_dir`.

**Migration**: пути в API файлов заменяются идентификаторами записи.

### Requirement: Папка результата в запросе

**Reason**: подпапки убраны, остаётся один каталог хранения.

**Migration**: параметр `folder` удаляется из запроса генерации.
