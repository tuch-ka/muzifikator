# Design

## Context

См. `proposal.md` — Why. Есть роутеры `api/` (задачи, файлы, настройки),
`OUTPUT_DIR` с листингом и защитой путей в `api/files.py`, `AssemblyService` с
фиксированным `output_dir`, `JobDeps` с тем же каталогом. UI нет. Владелец выбрал
статику без сборки, опрос стадий, новый seed при перегенерации и сохранение в
подкаталог.

## Goals / Non-Goals

**Goals:**

- Одна страница, которой достаточно API: без сборки, node и CDN.
- Подкаталоги результата без обхода защиты путей двумя разными реализациями.
- UI не ломает контракты задач и настроек.

**Non-Goals:**

- Проигрывание и стриминг аудио, история задач в UI сверх текущей.
- Выбор произвольного каталога вне `OUTPUT_DIR`.
- Фреймворк и сборка; тесты браузерного поведения в CI.

## Decisions

### 1. Статика в пакете

```
src/muzifikator/web/index.html
src/muzifikator/web/app.js
src/muzifikator/web/style.css
src/muzifikator/api/ui.py   # build_ui_router(): "/" и монтирование /static
```

`GET /` отдаёт `index.html`, `/static/*` — `StaticFiles` из каталога пакета.
Монтирование добавляется последним, чтобы не перехватить `/api/*`.
Никаких CDN: все стили и скрипт локальные, `style.css` — минимум для формы и
прогресса.

Проверка упаковки обязательна: hatchling должен включить `web/` в wheel; в
задачах — собрать wheel и убедиться, что файлы внутри (иначе UI пропадёт при
установке из пакета).

### 2. Интерфейс без фреймворка

`app.js` — один модуль с состоянием:

- при загрузке: `GET /api/settings`, `GET /api/voices`, `GET /api/files`;
- форма: текст (textarea), голос (select), теги (input), папка (input с
  `datalist` из подкаталогов листинга), кнопки «Сгенерировать» и
  «Сохранить настройки»;
- отправка: `POST /api/generations`; при `409` — сообщение и опрос уже идущей
  задачи по `generation_id` из ответа;
- опрос: `GET /api/generations/{id}` раз в секунду до `done`/`failed`, стадия
  показывается текстом и шириной полосы (tts 1/3, music 2/3, mix 3/3);
- результат: список файлов задачи (пути) и обновление листинга выбранной папки;
- «перегенерировать»: те же текст/голос/теги/папка, `seed` не передаётся — сервер
  возьмёт случайный.

Безопасность отображения: только `textContent`/`value`, никакого `innerHTML` с
данными сервера — текст пользователя не должен становиться разметкой.

### 3. Общий помощник путей

`src/muzifikator/paths.py`:

```python
class PathOutsideRootError(ValueError): ...
def resolve_within(root: Path, raw: str) -> Path
```

Правила: нет `\x00`, не абсолютный, `(root / raw).resolve()` внутри `root`.
`api/files.py` переводит ошибку в `400`, `assembly/service.py` — в
`InvalidFolderError`, роутер постановки — в `400` до создания задачи.

Так проверка пути существует в одном месте; сегодняшний код в `files.py`
переезжает в помощник.

### 4. Папка результата

- `GenerationCreate.folder: str | None`, `GenerationParams.folder`.
- Роутер постановки: если папка задана — `resolve_within(output_dir, folder)`;
  ошибка → `400` до записи и до запуска.
- `AssemblyRequest.subdir: str | None`; `AssemblyService.render` выбирает
  каталог: корень или `resolve_within(root, subdir)`, создаёт его и работает в
  нём (временные файлы тоже там — атомарность сохраняется в пределах одной ФС).
- Временные файлы и подбор имён остаются прежними; в листинге подкаталог виден
  через `GET /api/files?path=<folder>`.

Почему не отдельный `AssemblyService` на папку: сервис держит `MediaTools` и
настройки; создавать его на каждый запрос ради пути — лишний объект и
дублирование валидации.

### 5. Тесты

- `paths`: вложенный путь, `..`, абсолютный, симлинк наружу, пустая строка.
- `assembly`: рендер в подкаталог, создание вложенных уровней, отказ на выход за
  корень.
- API: постановка с папкой → файлы в подкаталоге и в `generation_files`;
  неверная папка → `400` без записи; листинг подкаталога видит файлы.
- UI: `GET /` — HTML с формой, `/static/app.js` и `/static/style.css` — `200`;
  в HTML нет внешних `http(s)`-ссылок на ресурсы.
- Ручная проверка браузером (Playwright, локально): заполнение формы из
  настроек, прогресс по стадиям, результат и список файлов, перегенерация,
  сохранение настроек. В CI браузерных тестов нет.

### 6. Ошибки и коды

| Ситуация | Код |
|---|---|
| Плохая папка в постановке | `400` |
| `409` при занятом движке | UI показывает сообщение и продолжает опрос текущей задачи |
| Статика отсутствует в пакете | падение теста упаковки, а не 200 с пустой страницей |

## Risks / Trade-offs

- Статика может не попасть в wheel → проверка сборки обязательна; иначе UI
  сломается только после установки из пакета.
- Опрос раз в секунду создаёт нагрузку на базу → личный инструмент, один
  пользователь; интервал можно увеличить без изменения контракта.
- Папки создаются по запросу пользователя → мусорные каталоги возможны; это
  осознанно, UI показывает только существующие.
- Логика UI не покрыта автотестами в CI → проверяется вручную и смоук-проверкой
  HTML/ресурсов; браузерные тесты — отдельное решение.
- `textContent`-дисциплина может быть нарушена будущими правками → в документе
  зафиксировано правило.
- Смена seed при перегенерации не воспроизводит трек → кнопка явно означает
  «новый вариант», а не повтор.

## Migration Plan

Схема БД не меняется. Данные — новые подкаталоги в `OUTPUT_DIR`. Откат — revert
коммита: старые файлы остаются, API задач без `folder` работает как раньше.

## Open Questions

Нет: технология, прогресс, перегенерация и папка зафиксированы владельцем.
