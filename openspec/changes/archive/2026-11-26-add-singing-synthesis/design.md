# Design

## Context

См. `proposal.md` — Why. Есть: `music/` (MusicGen, подложка), `assembly/`
(микс/экспорт), `jobs/` (пайплайн, стадии `tts/music/mix`, CHECK-ограничение в
БД), `web/`. Оценка подтвердила готовую русскую NNSVS-модель «Llane Crow»
(CeVOX Cantano): acoustic/duration/timelag `.pth`, hed, словарь, скалеры — в
GitHub-релизе. PyPI: `nnsvs` 0.1.1, `utaupy` 1.22.1, `pyworld` 0.3.6. Владелец
выбрал: song по умолчанию, вокал + подложка MusicGen + микс, только NNSVS.

## Goals / Non-Goals

**Goals:**

- Одна команда «текст + теги» даёт поющий трек с подложкой.
- Режим `song` — основной; `narrated` остаётся и не ломается.
- Детерминизм по seed, локальность, предсказуемые ошибки.

**Non-Goals:**

- Дообучение банка, выбор голоса в song, MIDI-вход, вокал без подложки.
- Робот-пение как результат — только dev-инструмент.

## Decisions

### 1. Раскладка и зависимости

```
src/muzifikator/singing/__init__.py
src/muzifikator/singing/melody.py      # процедурная мелодия (переносится из tools/eval)
src/muzifikator/singing/g2p.py         # русская графема → фонемы
src/muzifikator/singing/labels.py      # ноты + фонемы → UST / full-context labels
src/muzifikator/singing/nnsvs.py       # SingingBackend: синтез через nnsvs
src/muzifikator/singing/service.py     # SingingService: лирика → вокал WAV
```

Runtime-зависимости для song: `nnsvs`, `utaupy`, `pyworld`, `soundfile`.
Все ставятся в основное окружение; если импорт недоступен, song-задачи падают с
понятной ошибкой, а `narrated` продолжает работать.

### 2. Протокол

`SingingBackend` — `sing(lyrics, tags, seed, target: Path) -> float` (длительность)
и `name`; грузит модель лениво, один раз на процесс, детерминирован по seed.
`SingingService` строит мелодию, фонемы, лейблы и вызывает бэкенд; тест-замена —
фейковый бэкенд (пишет тон), поэтому сервис тестируется без NNSVS.

### 3. Мелодия

`melody.py` — из `tools/eval`: нота на слог, гамма из тегов (minor/major),
tempo из тегов, тоника в конце; `random` с seed → детерминизм. Возвращает список
`Note(syllable, midi, seconds)`.

### 4. G2P и лейблы

Русская G2P: берём таблицу фонем из `nnsvs-russian-support` (`dic/Russian.table`)
как словарь «слово → фонемная запись»? Это таблица OpenUtau, а не полный словарь
слов. Запасной вариант — набор правил (по аналогии с `hhskt_ru_phonemizer`):
слог → фонемы по простым правилам русского, покрывающим тестовые слова. Точность
проверяется прослушиванием; это и есть риск фазы.

Лейблы: `utaupy` читает UST (формат UTAU) и таблицу вопросов и превращает ноты с
текстом в full-context labels. Мы генерируем UST из мелодии и фонемной разбивки,
затем `nnsvs`-пайплайн (`nnsvs-run-synthesis` / `run.py synthesize`) синтезирует
WAV. Точная последовательность команд — предмет спайка (см. «Проверка»).

### 5. Подложка и микс

Вокал (WAV) + подложка MusicGen (по тегам, длиной `вокал + хвост`) сводятся в
`media.mix_tracks(vocal, backing, target, vocal_gain, backing_gain, tail)`:
`amix` без деления уровней, `loudnorm`, подложка тише вокала (0.35), хвост 2 с.
Экспорт MP3/M4A — через общий `media.encoders` (выносится из `assembly`).

`music/` остаётся без изменений: тот же MusicGen даёт подложку.

### 6. Режим задачи

- `GenerationCreate.mode: Literal["song","narrated"] = "song"`.
- Миграция: колонка `generations.mode` (TEXT, default `song`) и расширение
  CHECK-стадий до `('tts','music','mix','melody','sing')` через
  `batch_alter_table`.
- Пайплайн: `song` — `melody` (мелодия) → `sing` (вокал) → `music` (подложка) →
  `mix`; `narrated` — прежний путь. Голос в song не используется; в историю
  пишутся `mode`, `music_tags`, `music_seed`, голос пуст.
- `GET /api/generations` возвращает `mode`.

### 7. API и интерфейс

`POST /api/generations` принимает `mode`; неверное значение — `400` до создания
записи. UI: переключатель режима (song по умолчанию); в song поле голоса
`disabled`. Остальные эндпоинты не меняются.

### 8. Ошибки

`SingingError` → `SingingModelError` (веса/импорт), `SingingSynthesisError`
(падение модели), `SingingPhonemizerError` (G2P/лейблы). В song падение любой
стадии переводит задачу в `failed` с текстом; частичный вокал удаляется.

### 9. Проверка

- Спайк первым: скачать релиз модели, завести headless-синтез одной фразы из
  трёх слов в WAV (`nnsvs` + `utaupy`). Пока спайк не зелёный, остальное не
  интегрируется; блокер фиксируется.
- Юнит: `melody` (ноты, seed), `g2p` (тестовые слова), `labels` (UST содержит
  ноты и текст), `mix_tracks` (длительность, кодеки).
- Сервис: фейковый бэкенд → вокал WAV, seed-детерминизм, пустая лирика, ошибка
  бэкенда без частичного файла.
- Пайплайн: режимы song/narrated, стадии, запись в историю (`mode`).
- API/UI: валидация mode, `400` на неизвестный, состояние отдаёт mode.
- Реальный NNSVS — маркер `model`, вне дефолтного CI.

## Risks / Trade-offs

- **Главный риск**: headless-синтез NNSVS (лейблы из UST + правильные вопросы).
  Спайк решает это до интеграции; при неудаче фаза блокируется и возвращается к
  владельцу с фактами.
- Русская G2P грубая → слова могут произноситься неточно; прослушивание в
  верификации.
- `nnsvs`/`utaupy` старые и хрупкие → зависимости пин-ятся, окружение фиксируется.
- Миграция CHECK через batch пересоздаёт таблицу → SQLite-совместима, тест
  `upgrade/downgrade` обязателен.
- Детерминизм NNSVS между окружениями не гарантируется → спека ограничивает
  одним окружением (как у музыки).
- Память/время: NNSVS лёгкий, но модель в torch; замер в спайке.

## Migration Plan

Одна миграция: `mode` + расширение CHECK. Существующих данных нет (база
пересоздаётся); `downgrade` возвращает прежние стадии и удаляет колонку. Откат
кода — revert, зависимости `nnsvs`/`utaupy` удаляются из окружения.

## Open Questions

Нет: режим, подложка, только NNSVS и отсутствие выбора голоса зафиксированы.
Детали команд синтеза — результат спайка, а не вопрос.
