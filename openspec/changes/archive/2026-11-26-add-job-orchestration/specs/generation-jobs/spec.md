# Spec Delta

## Purpose

Даёт пользователю способ запустить генерацию и узнать её судьбу: одна задача
одновременно, видимые стадии, результат в базе и предсказуемые ответы при
занятости, ошибках и перезапуске.

## ADDED Requirements

### Requirement: Постановка задачи

Система SHALL принимать генерацию по тексту и параметрам голоса, создавать запись
со статусом `pending` и сразу возвращать её идентификатор, не дожидаясь
выполнения.

#### Scenario: Новая генерация

- **WHEN** приходит запрос с непустым текстом и существующим голосом
- **THEN** создаётся запись `pending`, ответ содержит идентификатор задачи и её статус

#### Scenario: Пустой текст

- **WHEN** текст пуст или состоит из пробелов
- **THEN** запрос отклоняется с кодом `422`, запись не создаётся

#### Scenario: Неизвестный голос

- **WHEN** запрошен голос, которого нет у провайдера
- **THEN** запрос отклоняется с кодом `400` и сообщением с именем голоса

#### Scenario: Неизвестный формат

- **WHEN** запрошен формат вывода, которого нет
- **THEN** запрос отклоняется с кодом `400` до создания задачи

### Requirement: Одна генерация одновременно

Система SHALL выполнять не более одной генерации. Пока задача выполняется, новая
постановка MUST NOT создавать вторую работу и SHALL получать `409` с
идентификатором текущей задачи.

#### Scenario: Движок занят

- **WHEN** приходит запрос, пока выполняется другая генерация
- **THEN** ответ `409` содержит идентификатор выполняющейся задачи, новая запись не создаётся

#### Scenario: После завершения

- **WHEN** предыдущая генерация завершилась
- **THEN** новая постановка принимается как обычно

### Requirement: Стадии выполнения

Выполнение SHALL проходить стадии `tts`, `music`, `mix` в этом порядке, и текущая
стадия SHALL быть видна через опрос состояния, пока задача в `running`.

#### Scenario: Ход выполнения

- **WHEN** задача выполняется
- **THEN** состояние показывает стадию `tts`, затем `music`, затем `mix`

#### Scenario: Завершённая задача

- **WHEN** задача завершилась
- **THEN** её статус `done` или `failed`, стадия больше не меняется

### Requirement: Опрос состояния

Система SHALL отдавать состояние задачи по идентификатору: статус, стадию, время
создания и завершения, длительность, файлы результата и текст ошибки.

#### Scenario: Успешная задача

- **WHEN** запрошено состояние завершённой задачи
- **THEN** ответ содержит `done`, длительность и пути файлов по форматам

#### Scenario: Неизвестная задача

- **WHEN** запрошен идентификатор, которого нет
- **THEN** ответ `404`

### Requirement: История задач

Система SHALL отдавать список последних задач от новых к старым с ограничением
количества.

#### Scenario: Список

- **WHEN** запрошен список с ограничением
- **THEN** возвращается не больше заданного числа записей, новые первыми

### Requirement: Ошибка пайплайна

При ошибке любой стадии задача SHALL переходить в `failed`, сохранять текст
ошибки и MUST NOT содержать файлов результата.

#### Scenario: Провайдер недоступен

- **WHEN** синтез речи падает с ошибкой
- **THEN** задача получает `failed` с текстом причины, файлы результата отсутствуют

#### Scenario: Сбой микса

- **WHEN** микс не удался после успешной музыки
- **THEN** задача получает `failed`, причина сохранена

### Requirement: Восстановление после рестарта

При старте система SHALL находить задачи, оставшиеся в `running`, и переводить их
в `failed` с причиной «прервано перезапуском».

#### Scenario: Прерванная задача

- **WHEN** приложение запускается после аварийного завершения во время генерации
- **THEN** такая задача читается как `failed` с причиной, а движок свободен для новой работы

### Requirement: Список голосов

Система SHALL отдавать список голосов провайдера с именем, локалью и полом.

#### Scenario: Голоса доступны

- **WHEN** запрошен список голосов
- **THEN** ответ содержит голоса провайдера, полученные не более одного раза за процесс

#### Scenario: Провайдер недоступен

- **WHEN** список голосов получить не удалось
- **THEN** ответ `502` с текстом причины, пустой список не возвращается
